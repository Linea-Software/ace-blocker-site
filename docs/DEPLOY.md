# VPS Deployment Guide for Ace Blocker

This guide provides a step-by-step walkthrough for deploying the Ace Blocker website to a Linux VPS (Ubuntu 22.04+ recommended) using **Docker**, **Bun**, **Nginx**, and **Certbot**.

---

## 📋 Prerequisites

1.  **A VPS**: (DigitalOcean, Hetzner, AWS, etc.) with at least 1GB RAM.
2.  **A Domain Name**: Pointed to your VPS IP address (A record).
3.  **Basic Linux knowledge**: Ability to SSH and run commands.

---

## 🛠️ 1. Initial Server Setup

Login to your server and perform basic security steps.

```bash
# Update system
sudo apt update && sudo apt upgrade -y

# Install basic tools
sudo apt install -y curl git ufw
```

### Setup Firewall
Allow SSH, HTTP, and HTTPS.
```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw --force enable
```

---

## 📦 2. Install Dependencies

### Install Docker & Docker Compose
The database runs in Docker.
```bash
# Install Docker
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# Add your user to the docker group
sudo usermod -aG docker $USER
# (Log out and back in for this to take effect)
```

### Install Bun
Used for package management and running the app.
```bash
curl -fsSL https://bun.sh/install | bash
source ~/.bashrc
```

### Install Nginx
Used as a reverse proxy.
```bash
sudo apt install -y nginx
```

## 🚀 3. Project Deployment

### Clone the Repository
```bash
git clone https://github.com/aintDatCap/ace-blocker-site.git
cd ace-blocker-site
```

### Initial Setup
Run the project's setup script to install dependencies, configure the initial `.env`, and start the database.
```bash
bun install
bun run setup
```

### Production Environment Variables
Edit the `.env` file for production.
```bash
nano .env
```
Ensure the following are set correctly:
- `DATABASE_URL`: Ensure it points to the docker DB (default should work).
- `BETTER_AUTH_SECRET`: Already generated by `setup`.
- `BETTER_AUTH_URL`: **IMPORTANT** - Change to `https://yourdomain.com`.
- `ORIGIN`: **IMPORTANT** - Set to `https://yourdomain.com`. (Required for SvelteKit CSRF protection).
- `DODO_PAYMENTS_API_KEY`: Your production API key.
- `DODO_PAYMENTS_WEBHOOK_SECRET`: Your production webhook secret.

---

## 🏗️ 4. Build and Run

### Build the Application
```bash
bun run build
```
This generates the output in the `.svelte-kit/output` (or `build/` depending on adapter) directory.

### Create a Systemd Service
To keep the server alive and restart on failure.

1. Create the service file:
```bash
sudo nano /etc/systemd/system/ace-blocker.service
```

2. Add the following content (adjust `/path/to/project` and `/your/user` as needed):
```ini
[Unit]
Description=Ace Blocker SvelteKit App
After=network.target

[Service]
Type=simple
User=your_username
Group=your_username
WorkingDirectory=/home/your_username/ace-blocker-site
EnvironmentFile=/home/your_username/ace-blocker-site/.env
ExecStart=/home/your_username/.bun/bin/bun /home/your_username/ace-blocker-site/build/index.js
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```
*(Note: Replace `your_username` with your actual Linux username, typically `ubuntu` or `root`.)*

3. Start and enable the service:
```bash
sudo systemctl daemon-reload
sudo systemctl enable ace-blocker
sudo systemctl start ace-blocker
```

## 🌐 5. Nginx Configuration

1. Create a new site configuration:
```bash
sudo nano /etc/nginx/sites-available/ace-blocker
```

2. Add the following content (Basic HTTP config):
```nginx
server {
    listen 80;
    server_name yourdomain.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```
*Note: The `X-Forwarded-Proto` header is essential for SvelteKit and Better Auth to correctly detect HTTPS.*

3. Enable the site and restart Nginx:
```bash
sudo ln -s /etc/nginx/sites-available/ace-blocker /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

## 🔒 6. HTTPS Support (SSL)

We recommend using **Certbot** for free, automatically renewing SSL certificates from Let's Encrypt.

### Install Certbot
```bash
sudo apt install -y certbot python3-certbot-nginx
```

### Obtain and Configure Certificate
```bash
sudo certbot --nginx -d yourdomain.com
```
Follow the interactive prompts. **Choose the option to Redirect HTTP to HTTPS** when asked. This will automatically update your Nginx configuration with:
- SSL certificate paths.
- Secure port 443 listening.
- HTTPS redirection rules.
- Modern SSL security parameters.

### Verify Auto-Renewal
Certbot adds a timer to your system to handle renewals automatically.
```bash
sudo systemctl status certbot.timer
```

## 💳 7. Webhooks (Dodo Payments)

Since the project uses Dodo Payments, you must configure the webhook URL in your **Dodo Payments Dashboard**:

1. Log in to Dodo Payments.
2. Go to **Developer > Webhooks**.
3. Add a new webhook with the URL: `https://yourdomain.com/api/auth/dodopayments/webhook`
4. Copy the **Webhook Secret** and paste it into `.env` as `DODO_PAYMENTS_WEBHOOK_SECRET`.

## 💾 8. Database Backups (Crucial)

To prevent data loss, schedule a daily backup of your Postgres container.

1. Create a backup script:
```bash
mkdir -p ~/backups
nano ~/backups/backup_db.sh
```

2. Add this content:
```bash
#!/bin/bash
BACKUP_PATH="/home/your_username/backups/db_$(date +%Y%m%d_%H%M%S).sql"
docker exec ace-blocker-site-db-1 pg_dump -U root local > $BACKUP_PATH
# Delete backups older than 7 days
find /home/your_username/backups -type f -name "*.sql" -mtime +7 -delete
```
*(Check your actual container name with `docker ps`)*

3. Make it executable and add to crontab:
```bash
chmod +x ~/backups/backup_db.sh
crontab -e
# Add this line at the end:
0 3 * * * /home/your_username/backups/backup_db.sh
```

sudo journalctl -u ace-blocker -f

```bash

```

## 🛠️ 11. Troubleshooting

### "CSRF Error" or "Invalid Origin"
Ensure the `ORIGIN` variable in `.env` exactly matches your domain (including `https://`) and that Nginx is passing the `X-Forwarded-Proto` header.

### Database Connection Issues
If the app cannot connect to the database, ensure the Docker container is running:
```bash
docker ps
```
If it's not running, check the logs with `docker compose logs`.

### Memory Issues (Low RAM VPS)
If your build fails or the app crashes on a 512MB/1GB VPS, add a swap file:
```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```
